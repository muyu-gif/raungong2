## 4. 认证流程

### 4.1 总体流程

```text
注册 / 登录
  → 拿到 access_token
  → 存入 Pinia + localStorage
  → 请求拦截器自动加 Authorization: Bearer <token>
  → 401 时清除 token，跳转登录页
```

### 4.2 注册

**`POST /api/v1/auth/register`**  
鉴权：无  
成功：`201`

请求：

```json
{
  "username": "demo",
  "password": "demo12345",
  "display_name": "演示用户"
}
```

字段规则：

| 字段 | 规则 |
|---|---|
| `username` | 3～32 位，只能是字母、数字、下划线 |
| `password` | 8～64 位 |
| `display_name` | 1～50 位 |

响应：

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "expires_in": 604800,
  "user": {
    "id": "9b2f6c1e-3a4d-4e5f-8a6b-7c8d9e0f1a2b",
    "username": "demo",
    "display_name": "演示用户",
    "role": "user",
    "created_at": "2026-11-03T11:33:57.445828"
  }
}
```

注册成功直接返回 token，前端可以直接进入工作台，不需要再登录一次。

错误：

```json
{
  "detail": {
    "code": "USERNAME_TAKEN",
    "message": "用户名已存在"
  }
}
```

HTTP `409`。

前端判断：

```ts
if (error.response?.status === 409 && error.response.data?.detail?.code === "USERNAME_TAKEN") {
  showMessage("用户名已存在，请换一个");
}
```

### 4.5 前端 Auth Store 示例

```ts
import { defineStore } from "pinia";
import { ref } from "vue";
import { api } from "@/api/client";

export const useAuthStore = defineStore("auth", () => {
  const token = ref(localStorage.getItem("token") ?? "");
  const user = ref<any>(null);

  function setToken(value: string) {
    token.value = value;
    localStorage.setItem("token", value);
  }

  function clear() {
    token.value = "";
    user.value = null;
    localStorage.removeItem("token");
  }

  async function login(username: string, password: string) {
    const { data } = await api.post("/api/v1/auth/login", {
      username,
      password,
    });
    setToken(data.access_token);
    user.value = data.user;
    return data;
  }

  async function fetchMe() {
    if (!token.value) return null;
    const { data } = await api.get("/api/v1/auth/me");
    user.value = data;
    return data;
  }

  return { token, user, setToken, clear, login, fetchMe };
});
```

### 4.6 请求/响应拦截器

```ts
api.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

api.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem("token");
      if (location.pathname !== "/login") {
        location.href = "/login";
      }
    }
    return Promise.reject(error);
  }
);
```

> 当前后端**没有刷新令牌接口**，token 有效期 7 天，过期后重新登录。

### 6.2 创建生成任务

**`POST /api/v1/plans/generate`**  
鉴权：Bearer  
成功：`202 Accepted`

请求头（可选）：

```text
Idempotency-Key: 6f1c2a9e-8b7d-4c3a-9e2f-1a2b3c4d5e6f
```

当前后端支持这个头，但**不是必填**。当前实现是：只要这个 key 已存在，就复用已有任务，没有“10 分钟窗口”的限制。前端每次新生成应使用新的 UUID；只有网络超时重试时才复用同一个 key。

请求体：

```json
{
  "theme": "迎新晚会",
  "activity_type": "welcome_party",
  "participants": 100,
  "budget_yuan": 2000,
  "starts_at": "2026-11-09T19:00:00+08:00",
  "duration_minutes": 120,
  "location": "学校礼堂",
  "target_audience": "2026级新生",
  "goals": ["帮助新生融入校园", "展示社团风采"],
  "constraints": "室内礼堂，禁止明火",
  "tone": "lively",
  "extra_notes": "希望有抽奖互动"
}
```

必填字段：

| 字段 | 类型 | 规则 |
|---|---|---|
| `theme` | string | 2～60 |
| `activity_type` | string | 2～32；前端用固定枚举 |
| `participants` | int | 10～2000 |
| `budget_yuan` | number | 0～1,000,000，最多两位小数 |
| `starts_at` | string | ISO 8601，带时区 |
| `duration_minutes` | int | 30～480，默认 120 |
| `location` | string | 1～120 |

可选字段：

| 字段 | 类型 | 规则 |
|---|---|---|
| `target_audience` | string | ≤120 |
| `goals` | string[] | ≤5 条 |
| `constraints` | string | ≤500 |
| `tone` | string | 默认 `lively` |
| `extra_notes` | string | ≤500 |

> 当前后端**不接受 `template_id`**，前端不要发送。

响应：

```json
{
  "task_id": "a33ffa9e-970c-4c86-ae09-20a5bbb113dc",
  "plan_id": "40f804eb-12aa-4d93-bb6a-12709bd772b1",
  "status": "queued",
  "reused": false,
  "estimated_seconds": 3,
  "poll_after_ms": 1000,
  "poll_url": "/api/v1/tasks/a33ffa9e-970c-4c86-ae09-20a5bbb113dc"
}
```

前端拿到后：

1. 保存 `plan_id`；
2. 保存 `task_id` 到 `sessionStorage`（页面刷新后还要继续轮询）；
3. 跳转生成进度页；
4. 每 1 秒轮询 `GET /tasks/{task_id}`。

> **重要：** `GET /plans/{plan_id}` 现在返回 `latest_task`。  
> 页面刷新后可以用 `latest_task.task_id` 恢复轮询；仍建议同时把 `task_id` 存在 `sessionStorage`，减少一次请求。

错误示例：

```json
{
  "detail": [
    {
      "type": "greater_than_equal",
      "loc": ["body", "participants"],
      "msg": "Input should be greater than or equal to 10",
      "input": 5
    }
  ]
}
```

HTTP `422`。

### 6.3 查询任务

**`GET /api/v1/tasks/{task_id}`**  
鉴权：Bearer  
成功：`200`

```json
{
  "task_id": "a33ffa9e-970c-4c86-ae09-20a5bbb113dc",
  "plan_id": "40f804eb-12aa-4d93-bb6a-12709bd772b1",
  "type": "generate",
  "section_key": null,
  "status": "succeeded",
  "stage": "done",
  "progress": 100,
  "message": "生成完成",
  "attempt": 1,
  "error": null,
  "created_at": "2026-11-03T11:33:57.465254",
  "started_at": "2026-11-03T11:33:57.468000",
  "finished_at": "2026-11-03T11:33:58.500439"
}
```

状态：

```text
queued / running / succeeded / failed
```

当前没有取消接口，`canceled` 只存在于模型里，前端不要做取消按钮。

失败时：

```json
{
  "status": "failed",
  "stage": null,
  "progress": 0,
  "message": "生成失败",
  "error": {
    "code": "MOCK_GENERATION_FAILED",
    "message": "plan not found",
    "retryable": true
  }
}
```

前端轮询建议：

```ts
async function pollTask(taskId: string) {
  const started = Date.now();
  while (Date.now() - started < 3 * 60 * 1000) {
    const { data } = await api.get(`/api/v1/tasks/${taskId}`);
    // 更新进度
    if (data.status === "succeeded") return data;
    if (data.status === "failed") {
      throw new Error(data.error?.message ?? "生成失败");
    }
    await new Promise((r) => setTimeout(r, 1000));
  }
  throw new Error("生成时间较长，请稍后在历史中查看");
}
```

阶段文案：

| `stage` | 文案 |
|---|---|
| `null` | 已排队 |
| `planning` | 正在生成策划案 |
| `done` | 生成完成 |

当前 Mock 只用到 `planning` 和 `done`，但前端应对未知 stage 显示“处理中”。

### 6.6 按节编辑

**`PATCH /api/v1/plans/{plan_id}/sections/{section_key}`**  
鉴权：Bearer  
成功：`200`

`section_key` 只能是：

```text
plan
materials
tasks
promotion
risks
review
```

请求：

```json
{
  "version": 1,
  "comment": "修改物资数量",
  "data": {
    "items": [],
    "summary": {}
  }
}
```

说明：

- `data` 必须是**该节的完整数据**，后端整体替换，不做字段级 diff；
- `version` 必须是当前方案版本；
- 编辑 `materials` 时，后端会重算每项 `subtotal_yuan` 和 `summary`；
- 编辑 `plan` 时，后端会重算 `budget.items[].amount_yuan`、`items_total_yuan`、`planned_yuan`；
- 其他节只替换，不重算金额；
- 编辑前方案必须是 `ready`；
- `comment` 当前只接收，不会写入版本历史（当前没有版本表）。

> 当前 `data` 只做 `dict` 接收，后端不会逐字段校验类型。前端必须自己保证 `quantity`、`unit_price_yuan` 是数字，`items` 是数组，避免把字符串写进数据库。

成功响应：

```json
{
  "plan_id": "40f804eb-12aa-4d93-bb6a-12709bd772b1",
  "section_key": "materials",
  "version": 2,
  "data": {
    "items": [
      {
        "id": "M1",
```

### 6.7 Markdown 导出

**`GET /api/v1/plans/{plan_id}/export`**  
鉴权：Bearer  
成功：`200`  
响应类型：`text/markdown; charset=utf-8`

查询参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `format` | `markdown` | 目前只支持 `markdown`/`md` |
| `inline` | `false` | `true` 时浏览器内预览，`false` 下载 |

响应头：

```text
Content-Disposition: attachment; filename="activity-mind-plan.md"; filename*=UTF-8''...
```

前端不能用 `window.open` 直接打开，因为不会带 token。必须用 Axios `responseType: "blob"`：

```ts
async function exportPlan(planId: string) {
  const res = await api.get(`/api/v1/plans/${planId}/export`, {
    params: { format: "markdown" },
    responseType: "blob",
  });

  const disposition = res.headers["content-disposition"] as string | undefined;
  const filename = parseFilename(disposition) ?? "活动智囊_活动方案.md";

  const url = URL.createObjectURL(res.data);
  const a = document.createElement("a");
  a.href = url;
  a.download = filename;
  a.click();
  URL.revokeObjectURL(url);
}

function parseFilename(disposition?: string): string | null {
  if (!disposition) return null;

  const utf8 = /filename\*=UTF-8''([^;]+)/i.exec(disposition);
  if (utf8) return decodeURIComponent(utf8[1]);

  const plain = /filename="?([^";]+)"?/i.exec(disposition);
  return plain?.[1] ?? null;
}
```

错误：

| HTTP | 响应 | 场景 |
|---|---|---|
| 400 | `{"detail":"目前只支持 markdown"}` | `format=pdf` |
| 404 | `{"detail":"方案不存在"}` | ID 错误/不是自己的 |
| 409 | `{"detail":"方案尚未生成完成"}` | `content` 为空 |

当前没有服务端 PDF。需要打印时用浏览器 `window.print()` + 打印 CSS。

## 9. 关键联调逻辑

### 9.1 生成页轮询

```ts
const TASK_KEY = (planId: string) => `plan-task:${planId}`;

async function startGeneration(payload: GeneratePlanRequest) {
  const { data } = await api.post<GenerateAccepted>(
    "/api/v1/plans/generate",
    payload,
    {
      headers: {
        "Idempotency-Key": crypto.randomUUID(),
      },
    },
  );

  sessionStorage.setItem(TASK_KEY(data.plan_id), data.task_id);
  router.push(`/plans/${data.plan_id}/generating`);
}

async function poll(taskId: string) {
  const started = Date.now();

  while (Date.now() - started < 180_000) {
    const { data } = await api.get<GenerationTask>(
      `/api/v1/tasks/${taskId}`,
    );

    progress.value = data.progress;
    stageText.value = data.message;

    if (data.status === "succeeded") return data;
    if (data.status === "failed") {
      throw new Error(data.error?.message ?? "生成失败");
    }

    await new Promise((r) => setTimeout(r, 1000));
  }

  throw new Error("生成时间较长，请稍后在历史中查看");
}
```

页面刷新时：

```ts
let taskId = sessionStorage.getItem(TASK_KEY(planId));

  taskId = data.latest_task?.task_id ?? null;
}

if (taskId) {

} else {
  showRetry();
}
```

### 9.3 错误提示统一处理

当前后端**没有统一 `error` 包装**，错误格式有三种：

```json
{"detail": "字符串"}
```

```json
{"detail": {"code": "VERSION_CONFLICT", "current_version": 2}}
```

```json
{"detail": [{"loc": ["body", "participants"], "msg": "..."}]}
```

建议：

```ts
export function getErrorMessage(error: any): string {
  const detail = error?.response?.data?.detail;

  if (typeof detail === "string") return detail;

  if (Array.isArray(detail)) {
    return detail
      .map((item) => `${item.loc?.join(".")}: ${item.msg}`)
      .join("；");
  }

  if (detail?.message) return detail.message;

  if (error?.response?.status === 500) {
    return "服务器内部错误，请稍后重试";
  }

  return "请求失败，请稍后重试";
}
```

### 9.4 日期与金额

- 输入：`starts_at` 用 `new Date(value).toISOString()` 发送，后端接受带 `Z` 的时间；
- 展示：后端 SQLite 返回的时间可能没有 `+08:00`，前端按本地时间格式化即可；
- 金额：JSON number，展示统一 `toFixed(2)`；
- 不要用 JS 浮点数直接累加预算，展示用后端返回的 `planned_yuan`。

### 9.6 真实智能体切换

真实智能体由后端环境变量控制，前端接口不变：

```text
AGENT_PROVIDER=langgraph | mock
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=...
LLM_MODEL=deepseek-chat
RAG_TOP_K=4
RAG_KNOWLEDGE_DIR=./knowledge
```

`langgraph` 使用 DeepSeek + BM25 RAG，默认 3 个节点：

```text
策划案 + 预算
→ 物资 + 分工
→ 宣传 + 风险 + 复盘
```

前端仍然调用同一个 `POST /api/v1/plans/generate`，不需要知道当前是 Mock、LangGraph 还是降级。  
如果后端降级生成，方案详情会返回：

```json
{
  "degraded": true,
  "content": {
    "warnings": ["智能体调用失败，已使用规则模板降级生成……"]
  }
}
```

前端在结果页显示“降级生成”提示即可。

## 11. 当前不能做的功能

以下功能前端不要接：

| 功能 | 原因 |
|---|---|
| 版本历史 | 没有 `versions` 接口 |
| 恢复版本 | 没有 `restore` 接口 |
| 重新生成某一节 | 没有 `regenerate` 接口 |
| 保存为模板 | 没有 `templates` 接口 |
| 使用模板新建 | `GeneratePlanRequest` 没有 `template_id` |
| 导出 PDF | 只支持 Markdown |
| 取消生成 | 没有 `cancel` 接口 |
| 归档方案 | 没有 `PATCH /plans` 接口 |

如果产品要求这些按钮，先和后端确认接口，不要先写前端调用。

## 13. 与《03-接口规范》的差异

| 设计文档 | 当前后端实际 | 前端处理 |
|---|---|---|
| `/api/v1/meta/enums` | 已实现 | 请求并缓存，失败回退本地常量 |
| `activity_type_label` | 列表/详情已返回 | 直接展示 |
| `latest_task` | 详情已返回 | 刷新后可恢复轮询 |
| `agent` 字段 | 不返回 | 不展示 |
| `template_id` | 不支持 | 不发送 |
| 删除/复制 | 已实现 | 正常开发 |
| 版本/模板/重新生成 | 未实现 | 隐藏入口 |
| PDF 导出 | 未实现 | 只做 Markdown + 打印 |
| 统一 `error` 包装 | 使用 `detail` | 兼容三种格式 |
| 时间带时区 | SQLite 返回不带时区 | 按本地时间展示 |
| `GET /plans` 筛选 | 只有 page/page_size/keyword | 不做状态/类型筛选 |

## 14. 推荐开发顺序

1. API client + Auth Store + 登录/注册页；
